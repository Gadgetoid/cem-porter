CEMSync

Your device, no period PC required.

Talks to a Windows CE device from the browser: the Casio BE-300 over its own PC Connect protocol, the Dell Axim X51v (Windows Mobile 5) over ActiveSync, and the HP Jornada 720 and other Windows CE 2.x and 3.0 devices over PC Link, by USB or a serial cable.

Using it

  • Connect the cradle, press Connect, and choose the device when the browser asks.
  • The BE-300 answers with its Unit ID and the names of its system and user disks; the Axim with its name, model, OS version and processor.
  • Files browses the device, and sends, saves and deletes files.
  • Drop an installer, archive or CD image to find the packages the device takes: .cbea for the BE-300, CE .cab for the Axim. Packages built for another CPU are listed but not installed. Install sends the package and starts the device's own installer; follow its prompts there.
  • BE-300: Back up flash reads all 16 MB, the OS partitions included, and saves it.

Needs

  • Chrome or Edge. Safari and Firefox do not implement WebUSB.
  • On Linux, a udev rule, or the kernel's ipaq and rndis_host drivers will claim the device first.
  • Axim: leave Enable advanced network functionality on (Settings, Connections, USB to PC), and no device password.
  • Jornada and other PC Link devices: start PC Link on the device. The Jornada only appears on USB while PC Link is connecting, so choose it quickly the first time; after that CEMSync connects on its own whenever PC Link starts.
  • Serial: Connect Serial Port... takes any serial port or USB serial adapter. Start PC Link on the device; CEMSync finds the speed itself.

How it works

The BE-300 speaks Casio's own PC Connect protocol rather than ActiveSync. The host asserts DTR and RTS, trades 0x55 twice, then sends framed commands. The device drops off the bus about 115 ms after connecting if nothing follows, so the first command goes out immediately.

Flash reads below the file system use a negative sector offset: the driver maps the user volume at physical sector 7584 and only bounds checks the top of its window, so the OS partitions are readable through the ordinary call.

Windows Mobile 5 ActiveSync runs over TCP/IP on an RNDIS network over USB. CEMSync carries that network itself: RNDIS, Ethernet, ARP and a small TCP, with the PC at 169.254.2.2 and the device at 169.254.2.1. A 0x7F byte to the device's UDP port 5679 makes it connect to the PC's port 990, describe itself, and on request open a second connection carrying RAPI.

The device's network stops passing data once a session ends, until its USB configuration is cleared, so a later Connect resets the device first.

Older devices dial in. The device sends CLIENT, CEMSync answers CLIENTSERVER and plays the PC's side of PPP, giving the device 192.168.131.201. The device then connects to the PC's port 5679, describes itself and expects a ping every second, while CEMSync opens RAPI on the device's port 990.
